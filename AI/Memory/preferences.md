# 第一类 · 用户偏好与协作约定

> 跨项目稳定、长期有效的用户偏好与协作规则。新会话启动时，AI 应先读本文件再开始工作。

## 写入规则（AI 必读）

1. **写什么**：用户明确表达的偏好、反复出现的纠正、稳定的技术栈与环境约定、协作节奏要求。
2. **不写什么**：一次性任务进度、临时状态、单次 bug 修复过程、提交号、版本号（除非是长期约束）、敏感信息。
3. **格式**：每条以 `- ` 开头，尽量一行写完；需要说明时换行缩进。
4. **更新方式**：发现新的稳定偏好时，在对应小节追加；旧的被推翻时，**替换**而非保留冲突条目，并在条目末尾用 `（更新 YYYY-MM-DD）` 标注。
5. **来源标注**：能确认来源的条目末尾加 `（来源：用户明确说明 / 反复纠正 / 环境检查）`。
6. **确认机制**：会话收尾时，AI 主动问"本次是否有需要沉淀到 preferences 的偏好？"，用户确认后由 AI 写入；不擅自归档未确认的推测。

## 沟通方式

- 默认中文，先结论后原因，简洁不重复。（来源：用户明确说明）
- 用户表达跳跃或混乱时，AI 先归纳主线，不跟着发散。（来源：用户明确说明）
- 工具调用较多时，只汇总结论、关键证据和异常，不重复粘贴原始输出。（来源：反复纠正）
- 不写公文腔、不过度客气、不为鼓励而无脑肯定。（来源：用户明确说明）

## 工作方法

- 先判断真实目标和交付物，再检查材料是否充足；能工具补齐的先查不反问。（来源：用户明确说明）
- 大任务拆成有依赖的少量步骤，优先推进最重要的一条线。（来源：用户明确说明）
- "完成"= 实际修改/构建/测试/核验，不停留在计划；涉及部署须访问线上确认。（来源：用户明确说明）
- 高风险操作（删除、覆盖配置、暴露 Secret、强推、生产发布）先确认范围与回滚方案。（来源：用户明确说明）

## 技术环境（稳定事实）

- 主机：Windows 11，用户目录 `C:\Users\GhostCloud`。（来源：环境检查）
- Shell：Windows PowerShell 5.1（非 bash/cmd），用 `;` 分隔命令，`$env:VAR` 取环境变量。（来源：环境检查）
- 本机 HTTP/HTTPS 代理：`http://127.0.0.1:12450`，访问境外 API 直连失败时优先用此代理验证。（来源：用户明确说明）
- 主力 AI 工具：Hermes Agent CN Desktop（Windows 桌面版），非 CLI/TUI。（来源：用户明确说明）
- 另有 WSL 中的 Hermes 实例（root 运行，配置目录 `/root/.hermes`，监听 WSL LAN:9139，Basic Auth，凭据仅在 WSL 本地 0600 文件），与 Windows 桌面版分开判断。（来源：用户明确说明）

## 长期记忆与隐私

- 长期记忆只存脱敏后的稳定摘要，不存原始文件、聊天原文、密码、Token、API Key、证件、医疗、合同、私人照片。（来源：用户明确说明）
- 记忆维护流程：先分析、再整理、再手动写入、最后召回验证；禁止自动写入未筛选信息。（来源：用户明确说明）
- 微信数据不通过数据库解密/内存读取访问，优先手动转发、复制或文章链接入库。（来源：用户明确说明）
- 外部记忆服务（Hindsight 等）使用前明确数据流向、认证、稳定性、隐私边界。（来源：用户明确说明）

## 验证标准

- 涉及当前事实、版本、价格、网页内容、产品能力、MCP、部署状态时，回答前联网核验（优先 Firecrawl）。（来源：用户明确说明）
- 涉及本地文件、路径、配置、Git 状态时，先用工具检查再下结论。（来源：用户明确说明）
- 区分四种证据状态：已验证 / 用户明确提供 / 合理推断 / 目前未知；不确定的明确说不确定，不猜。（来源：用户明确说明）
